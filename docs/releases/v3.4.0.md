# JP Site Operations v3.4.0 — Google Sheets + Semantic Google Docs Backend

**Release gate:** create this tag only after a `main` workflow validates and deploys the exact commit to GitHub Pages. The release workflow checks successful project and deploy jobs in the matching Operations from Google Sheets run.

## Authoritative state

- Seven original live Google Sheets own all structured project, publication-setting, organization, source-message, site-notification, project-work and source-directory records. Existing IDs and row values are unchanged.
- Eight newly-created native Google Docs in private [GPT/02_SEMANTIC_GOOGLE_DOCS](https://drive.google.com/drive/folders/1Wvj8Xe_-kTi_z1t8VoTMJD1DSsiKvZQf) own a versioned human semantic explanation and an index mapping each Sheet to its exact tab.
- Only read-only Google Workspace API access is used by GitHub Actions. Service-account Reader rights are granted on those eight semantic Docs and Sharada's reviewed original Google Doc POST.
- Each authenticated production run reads all semantic Docs, checks the index and per-source contracts, double-reads original Sheets for concurrent changes, reads the original reviewed Google Doc POST snapshots registered in Message Sources, validates SHA256/byte count and quoted statements, and then renders public-safe HTML/JSON.
- Source records determine publication and closure permissions. AI may help a human prepare reviewed data but no autonomous LLM approval or silent editing is claimed.
- GitHub is a website-layout and workflow-code repository; historic `ops/data` examples are not the live public source. All generated `_site` files remain deploy artifacts, not data masters.
- Company-specific map colors, clean public labels and Drive-only gallery for the 22 historical Kharika instructions remain unchanged.
- The five Sharada site notifications remain unverified inspections/plans unless field evidence and human approval says otherwise.

If Google Docs API access, approvals or original source checks fail, do not deploy a new public projection; retain the previous successful Pages state and investigate source permissions/schemas. A rollback uses the pinned v3.3.0 Git commit and preserves Google source IDs.

## QA gates

- Offline semantic index parsing rejects missing/mismatched role/source/tab/private promotion.
- Actual Google Docs API reads succeed with Documents.Readonly scope; original Google Sheets double-read succeeds with Sheets.Readonly.
- All seven contract Docs are validated; each registered published Google Doc POST passes SHA256 and exact reviewed-quote check.
- Current published counts and hidden legacy count remain correct; site identity/company grouping and mobile controls still pass.
- Successful GitHub Actions `project` AND `deploy` jobs on the same `main` SHA; only then may the v3.4.0 release job create the tag.

This is a source-integration release, **not** certification of construction progress or retroactive closure of any task.
